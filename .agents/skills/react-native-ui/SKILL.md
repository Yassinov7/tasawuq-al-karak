# تسوق — هندسة واجهة الهاتف

## ابدأ من الواقع وحدد صفحة واحدة

اقرأ `PROJECT_RULES.md` و`WORK_PROGRESS.md` من جذر المشروع قبل العمل. حدد رقم RUI ومسار الصفحة وحالتها والتبعيات المفتوحة. اقرأ صفها في `docs/screen-inventory.ar.md` وخطتها في `docs/role-page-roadmap.ar.md`، ومرجع `docs/design-system.ar.md` وقاموس `docs/ui-text-glossary.ar.md`. اقرأ [قائمة مراجعة الصفحة](references/page-review.ar.md) عند بدء الصفحة، لا تكتف بفحص الشكل.

**لا تنفذ أكثر من صفحة رئيسية واحدة أو صفحة فرعية واحدة في الدفعة الواحدة.**

عند الانتهاء توقف وقدم خطوات اختبار الهاتف؛ لا تبدأ التالية قبل قبول المالك. الصفحة الفرعية الجديدة لها رقم وموافقة مستقلة ولا تضم تلقائيًا إلى الرئيسية. لا تعِد بناء وظائف مقبولة أو تغلق UX/UI/TXT تاريخية بلا دليل. تحديث الجرد لا يعني إنجاز الصفحات. اتبع طلب المالك الحالي عند تعارض النطاق مع ترتيب قديم، مع تسجيله.

## افحص قبل أن تنشئ

**ابدأ بأهداف الصفحة ومخططها البصري، ثم قيّم المكونات الموجودة وظيفيًا وبصريًا. أعد استخدامها أو تصميمها أو استبدلها بحسب ملاءمتها؛ إعادة استخدام الشكل القديم ليست أفضل دائمًا.**

حدد التركيب المرغوب وكثافة المعلومات وارتفاع الترويسة والفلاتر والبطاقة المغلقة قبل كتابة الواجهة. لا تجعل نجاح المنطق أو وجود مكون قديم سببًا لفرض شكله. إذا كان تركيب الصفحة غير مناسب، أعد بناء العرض بدل سلسلة تعديلات padding وألوان. حافظ على توافق المستهلكين الآخرين عند تغيير المشترك، أو أنشئ عنصرًا متخصصًا أوضح. اختبارات الكود لا تعني قبول التصميم؛ مشاهدة المالك على الهاتف وقبوله البصري شرط الإغلاق، حتى لو نجحت كل الاختبارات.

ابدأ من `docs/component-inventory.ar.md` ثم اقرأ كود المكون وprops والمستهلكين الفعليين. قوائم imports في الجرد محافظة وليست إثبات عرض أو صلاحية. لا توسع مكونًا إلى عشرات شروط الأدوار؛ أبقِ منطق الدور في شاشة/خدمة متخصصة. إصلاح مشترك مسموح بقدر ضرورة الصفحة الحالية؛ اذكر المستهلكين المتأثرين واختبرهم دون فتح إعادة تصميم لباقي الصفحات. انقل reusable من routes تدريجيًا فقط عند الحاجة. لا تحذف ملفًا قبل تتبع imports/scripts والروابط؛ أرشف مرجعًا ميتًا فقط حسب قواعد المشروع.

## تقنية Native فعلية

اقرأ package.json ونسخ lockfile قبل استخدام API أو إضافة حزمة. الأساس عند إنشاء المهارة: Expo SDK 57 وExpo Router 57 وReact Native 0.86.3 وTypeScript 6؛ لا تثبت هذه النسخ كحقيقة أبدية. راجع الوثائق الرسمية الموافقة للنسخة. استخدم View/Text/Pressable/FlatList والمكونات الموجودة، لا CSS/DOM أو مكتبة واجهات ويب. npm؛ حزم Expo عبر expo install عند ضرورة مبررة. لا تعديل مشاريع ios/android مولدة، ولا native config لعمل تجميلي، ولا dependency لمجرد toast أو skeleton متاحين.

## وظيفة قبل الزينة

حدد المستخدم والهدف وأول معلومة والإجراء الأساسي والحالات المحتاجة تدخلًا. أبقِ الرئيسية لوحة تشغيل مختصرة؛ لا تكرر التبويبات في شبكة اختصارات. التفاصيل والقوائم المستقلة حسب حاجة مثبتة. لا تظهر عدد صفحة محملة كإجمالي؛ استخدم المصدر الموثوق للعداد والأهلية. لا تستنتج أهلية المتجر من الرصيد أو الموافقة فقط. الروابط تعرض الحالة/الفلتر المقصود وتعمل عند الفتح المباشر؛ المرجع المقروء لا يمنح صلاحية.

## تصميم وثيمان

### مرجع Compact Mobile Dashboard المعتمد

رئيسية التاجر RUI-MER-01 مقبولة نهائيًا على هاتف المالك للتصميم والوظائف والثيمين والمسافات. أي تعديل صغير لاحق يتتبع بقبول مستقل ولا يعيد فتح الصفحة المقبولة. اعتمد: عرض الهاتف بكفاءة؛ مسافات عمودية متجاوبة من مساحة المحتوى والخط؛ مكونات مشتركة؛ ترتيب بحسب الأهمية؛ لا تكرار؛ هوية ليلية مريحة؛ تحميل ثابت لا يعيد تموضع العناصر؛ تفاعل وإتاحة وأهداف لمس؛ حالات ذات نص وتباين؛ وسلامة الإجراءات المالية والتشغيلية قبل الشكل. راجعها صفحةً صفحة، لا بتعميم تغييرات على المشروع دفعة واحدة.

اعتمد المالك الاتجاه المدمج لرئيسية التاجر مرجعًا للفلسفة، وليس قالبًا واحدًا يفرض على كل صفحة. عند الوصول إلى الصفحة الحالية فقط: استغل عرض الهاتف بصفوف وشبكات مرنة، واضبط كثافة المعلومات بحسب الوظيفة. قلل البطاقات الكبيرة والمسافات غير المبررة، ولا تكرر المعنى بين عنوان وبطاقة ورسالة. أبرز المعلومة والإجراء بدل الزينة. صمم الداكن كهوية متكاملة بأسطح وحالات متوازنة؛ حافظ على النهاري المقبول. حسّن المشترك قبل إنشاء بديل، دون توسيع النطاق إلى صفحاته الأخرى. لا تفرض منع التمرير: الصفحات الطويلة والخط المكبر تحتاج التفافًا وتمريرًا طبيعيًا؛ حافظ على أهداف اللمس والإتاحة. قبول الفلسفة لا يغلق أي صفحة أو يجيز إعادة تصميم المشروع دفعة واحدة.

الوضع النهاري مرجع جيد: أخضر محلي، قمحي، عاجي، Cairo. حافظ عليه. استخدم Typography/Spacing/Radius/ControlSizes/LayoutSpacing ورموز theme.ts؛ لا ألوان حرفية أو مقاسات عشوائية بلا سبب. الثيم الداكن له أسطح ونصوص وحالات خاصة، لا نقل ألوان النهاري إليه. افحص كل زوج foreground/background وحالات الضغط والتحديد والتعطيل والتركيز. المرجع يوثق عيوبًا لا يصلحها تلقائيًا؛ أي تغيير token عالمي يحتاج إثبات أثره على المستهلكين، ولا ينفذ خلسة ضمن صفحة.

النجاح والإجراء الأخضر ليسا المعنى نفسه؛ أضف نصًا/رمزًا. الانتظار/المعالجة لهما كلمة واضحة، لا شارة خضراء توحي بالنجاح. المال المستحق ليس خطأ أحمر تلقائيًا. نصوص عادية تستهدف 4.5:1 والكبيرة 3:1 مع مراعاة الاستثناءات؛ حدود عناصر تفاعلية تستهدف 3:1 عند الحاجة، لا تفرضه على كل فاصل زخرفي. الحساب اللوني ليس اختبار هاتف.

## هاتف عربي وإتاحة

استخدم spacing منطقيًا start/end، ومحاذاة عربية واتجاه صف مدروس دون عكس مزدوج. اختبر ORD/SOR/TSK وأرقام الفواتير والعملة والتواريخ والبريد داخل RTL؛ لا تعكس السلاسل المرجعية. لا تعطّل تكبير الخط لتثبيت البطاقة؛ اسمح بالتفاف النص وارتفاع مرن. هدف لمس لا يقل عن 44، وأزرار/حقول المشروع 48 حيث ينطبق. وضح accessibilityLabel/Role/State، أخفِ زخارف skeleton عن القارئ، ولا تعلن كل تحديث خلفي كرسالة عاجلة.

راجع SafeAreaInsets والترويسة والتنقل ولوحة المفاتيح؛ مالك واحد لكل padding سفلي، لا تتراكم مساحة شريط الدور مع صفحة مشتركة. استخدم KeyboardAwareScrollView للنماذج ولا تتداخل مع KeyboardAvoidingView آخر. راجع focus الحقول، نوع لوحة المفاتيح، رسالة الخطأ قرب الحقل، حفظ المدخلات، وتمرير الحقل والزر فوق الكيبورد. لا تجعل كل شيء ScrollView لقوائم كبيرة؛ استخدم virtualization ومفاتيح ثابتة وصور مناسبة. الإجراءات المتكررة ضمن وصول اليد، والحساس واضح وصعب النقر العرضي.

## دورة البيانات واستقرار الصفحة

ميز: تحميل أول، تحديث خلفي، تحديث يدوي، إجراء، فشل جزئي، فراغ حقيقي. LoadingSkeleton ثابت مناسب للبنية، RefreshStatus يحجز حيزًا، spinner محدود للإجراء؛ لا تحذف الصفحة مع كل حدث ولا تعرض صفرا كبيانات ناجحة. أبقِ بيانات الحساب نفسه عند فشل تحديثها مع وصف أنها لم تؤكد؛ أخفِ بيانات حساب/طرف/فلتر سابق فور تغير النطاق. لا تخفِ فشلًا أو تعرض نجاحًا كاذبًا بعد مهلة.

أعد استخدام useLiveUpdates/useOrderRealtime وقراءة النطاق/طابور السائق؛ افحص الاعتماديات الثابتة وAppState/Focus والتنظيف والإلغاء وتسلسل الردود. لا polling أو اشتراكات متكررة لكل render، ولا toast لكل reconnect. نجاح القراءة لا يساوي اتصال Realtime. اختبر أول SUBSCRIBED والخطأ/المهلة/CLOSED والعودة؛ اقرأ آخر إصلاح مقبول قبل تعديل الآلية. فشل Push لا يفشل العملية الأصلية. لا تعِد جلب بيانات كاملة لعداد فقط.

## نصوص ورسائل وتنقل آمن

طبق القاموس وسجل TXT الخاص بالصفحة فقط. عنوان الزر يصف فعله؛ اشرح السبب والخطوة التالية عندما تعرفهما دون كشف تفاصيل SQL/RPC/Migration للمستخدم. Toast عابر للأحداث المناسبة، خطأ مستمر داخل الشاشة، وحوار عند القرار. استخدم useToast ونظام منع التكرار الحالي، وuseAppDialog/AppModal للتأكيد؛ لا Alert أصلي ولا نجاح عند فتح الشاشة/تحديث تلقائي.

راجع إشعارات الحساب/الدور، جلسة الخروج والتبديل، اسم المرجع والوجهة، رفض الرابط غير المملوك، والرجوع دون history عبر الآلية الحالية. لا تثق بـPush payload كإذن. لا أسرار/عناوين/مبالغ حساسة في push أو logs؛ permission رفضها خيار لا يحجب الاستخدام الأساسي. لا تدعِ Push مغلق/خلفية من اختبار Expo Go أو من إعداد فقط.

## المالية لا تتغير لأجل العرض

الخادم مصدر النتيجة، المبلغ دقيق، الإجراء ذري وصلاحياته ثابتة. لا تغيير معادلات/تخزين/قبول طلب أو اشتراك لمجرد UI. ميز: مستحق لك، مطلوب منك دفعه، محصل، مدفوع، ونقد فعلي في الخزينة. حدد هل المقصود التاجر أو السائق أو المنصة؛ لا لون أو إشارة سالبة وحدها. السائق يسلم كامل التحصيل وأجره منفصل؛ لا مقاصة. صدور المستند منفصل عن سداده.

لوحة مختصرة وتفاصيل منفصلة عند الحاجة؛ SET/COR من فاتورة معلومة مع الطرف والمرجع والمبلغ والأثر والسبب والتأكيد. فتح التفاصيل لا يكتب. INV/SUB/SAL/DLV تنتج من الحدث التشغيلي، لا نموذج إدخال حر؛ WAG/الراتب مؤجل للإطلاق. العملية غير المحسومة تعرض ملخصها وتتحقق بالمفتاح المحفوظ نفسه؛ لا مفتاح جديد/عملية بديلة فوق نتيجة مجهولة. لا إلغاء كاتب مالي بدعوى إلغاء قراءة. لا optimistic success مالي.

## قبول وتسليم

اختبر النطاق المتغير والرد المتأخر وتبديل الحساب والصلاحيات والفراغ والخطأ الجزئي والإجراء المزدوج والرجوع المباشر والتحديث الحقيقي؛ أضف اختبارات سلوكية ذات قيمة دون نسخ التنفيذ. شغل expo lint وtsc --noEmit واختبارات السلوك المناسب مرة بعد آخر تغيير. Expo Doctor/build عند تغير اعتماديات/native config فقط بحسب الحاجة.

سلّم الملفات والنتيجة وحدود الإثبات واختبارات هاتف قصيرة: فاتح/داكن، RTL وأرقام، خط مكبر وشاشة صغيرة، كيبورد، شبكة/خلفية، صلاحية وتنقل، وحساس مالي إن تأثر. الكود المكتمل ينتظر قبول المالك؛ Android لا يغلق iOS. تحديث DB إن ثبتت ضرورته migration مستقلة يطبقها المالك، لا وصول لقاعدته. عند القانونية/التسجيل/الاشتراكات اقرأ STORE_POLICIES.md ووثائق Google/Apple الحديثة؛ لا تختلق قناة دعم أو حذف حساب أو التزام قانوني أو إعفاء دفع. سجل قرار المالك اللازم ولا تفترضه.

حدّث WORK_PROGRESS والجرد والقاموس عند تغير ما يوثقونه، ثم توقف عند الصفحة الحالية.
