## تغيير مهم في provenance عمليات C2 المجدولة

C2 كانت تشترط actor_id/actor_role غير فارغين، ودوالها الإنسانية تشترط auth.uid. فوترة تلقائية حقيقية دون فتح التطبيق لا يجوز أن تنتحل JWT موظف.

Migration C8 تضيف system_source، وتستبدل NOT NULL المنفردين بقيد مزدوج:

- عملية بشرية: actor_id وactor_role موجودان، system_source فارغ، كما قبل C8.
- عملية النظام: الحقلان فارغان معًا، وsystem_source='subscription_scheduler'، والنوع حصريًا c8_issue.

أضيف تفرد مستقل لمفتاح العملية النظامية. لم تتغير دوال C2 البشرية ولا تحققها من auth.uid. إنشاء العملية/الحدث النظاميين وإكمالهما محصور في helpers خاصة، لا في RPC للتطبيق. `post_journal` الحالي يتحقق من تطابق actor؛ سياق المجدول NULL يطابق مصدر العملية النظامي NULL، بينما مستخدم التطبيق غير الفارغ لا يطابقه. قيود التوازن والترحيل والعكس والفحوص المؤجلة باقية.

المجدول يشترط auth.uid فارغًا وsession_user=current_user (مالك الدالة/اتصال قاعدة موثوق)، ولا يضبط claims ولا ينتحل مستخدمًا. finance_private غير متاح لـanon/authenticated/service_role، والدوال SECURITY DEFINER بمسار بحث فارغ. لا إنشاء مستخدم خدمة أو أسرار في التطبيق.

**هذه إضافة عقد مخطط مهمة تحتاج مراجعة المالك واختبارات PostgreSQL/JWT قبل الاعتماد**؛ اختبارات المصدر لا تثبت عدم تصعيد الصلاحيات. يلزم توليد الأنواع بعد تطبيق بيئة اختبار ومراجعة nullable actor/source فيها؛ لم تُوصف عقود التطبيق اليدوية بأنها مولدة.

## الخطط والانتقال

إعادة استخدام subscription_plans لتعريف الخطة والعمولة وحدود المنتجات، مع subscription_plan_versions immutable لاسم/وصف/سعر/مدة/إتاحة/تاريخ السريان والسبب والموظف. يمكن إنشاء التعريف الأساسي من صفحة الإدارة الموجودة، ثم إعداد إصدار C8 بتفويض plans المستقل. لا يستبدل تغيير الإصدار سعر فاتورة أو شروط فترة مدفوعة قديمة.

الإيقاف يمنع إصدار فواتير جديدة؛ لا يلغي فاتورة صادرة أو فترة مدفوعة. تحفظ الفاتورة مرجع إصدار الخطة والسعر وبداية ونهاية الفترة المجدولة. تعرض واجهتها الفترة الفعلية عند السداد منفصلة عن الفترة المجدولة، خصوصًا بعد انقطاع تجاوز السماح.

لا تحويل تلقائي لـlegacy. `enroll_subscription_account` إجراء إداري صريح بتفويض issue وسبب، لا يعمل إلا عند فتح accept_operations وenforce_gate. يرفض وجود فترة legacy سارية أو مستقبلية أو ضمن السماح، ويرفض فواتير legacy غير مسددة/غير ملغاة، أو دفعات قديمة غير مخصصة، أو ذمة C2 غير صفرية قبل الانتقال. يجب أن يكون أحدث إصدار خطة صالحًا ومتاحًا. لا نقل ديون قديمة أو إعادة ترحيلها في C2.

تظل الحسابات غير المنضمة على السلوك السابق. بمجرد إدخال الحساب صراحة تصبح عضويته immutable وتبقى بوابته سارية حتى لو أغلق المالك قبول مجموعات جديدة. إيقاف العلم العام لا يفتح متجرًا معلقًا أو منتهيًا. لا مسار خروج/تحويل رجعي أو إسقاط دين صامت.

## دورة التجديد والقبض

اختيار التجديد محفوظ بأحداث immutable مع تسلسل وهوية وتوقيت وسبب: automatic/manual/disabled. لا يغير فاتورة موجودة. اختيار automatic يعني إصدار فاتورة عند نهاية آخر فترة مدفوعة فقط، وليس دفعًا تلقائيًا.

اليدوي: المالك يختار manual ثم يطلب فاتورة. الموظف المخول issue يستطيع إصدارًا إداريًا بسبب واضح. توجد فاتورة واحدة لكل anchor، وفاتورة افتتاحية واحدة. أي فاتورة غير مدفوعة قائمة يعاد استخدامها بسعرها القديم، ولا يضاف دين آخر. دفع فترة مستقبلية يمنع إصدار الفترات التي بعدها حتى تبدأ تلك الفترة.

القبض: موظف مخول collect، والمبلغ المعدود يساوي كامل الفاتورة. لا سداد جزئي ولا وسيلة إلكترونية أو رصيد غير مخصص. تقفل C8 صف التاجر بـFOR NO KEY UPDATE ثم mutex الخزينة المشتركة مع C6/C7 ثم الفاتورة. NKU مهم: يسمح بمفاتيح C7 الأجنبية المتجهة إلى التاجر أثناء انتظار mutex، ويمنع دورة deadlock مع FOR UPDATE.

بعد التحقق من ذمة C2 والقيد الأصلي، ينشأ RCT والقيد وفترة merchant_subscriptions التشغيلية في معاملة واحدة. native periods لا تُنشأ قبل القبض. تفرد invoice_id/period_id/الحدث يمنع الدفع أو التفعيل المزدوج. فحص مؤجل يطابق كامل المبلغ والخطة والنسبة والمدة وبداية ونهاية الفترة والقيد المتوازن. فشل أي trigger يعيد القبض والفترة والنتيجة معًا.

- الدفع قبل النهاية أو خلال السماح: البداية عند نهاية الفترة السابقة.
- الدفع عند نهاية168 ساعة بالضبط أو بعدها: البداية عند وقت القبض الفعلي.
- مدة الأشهر تُضاف إلى التاريخ في UTC ثم يعاد timestamptz؛ لا حسابات أشهر في JavaScript.
- نهاية السماح = نهاية المدفوع +168 ساعة فعلية، وليست سبعة أيام محلية متأثرة بـDST.

المحاولات محفوظة لكل حساب وmerchant مع مفتاح ومدخلات ثابتين. الاستعادة تسبق إعادة الإرسال، والرفض التجاري نهائي قابل للاستعادة، والمهلة ليست إثبات فشل. لا مفتاح مستقل قبل التحقق من النتيجة النهائية. مفتاح مختلف لفاتورة مدفوعة يعيد RCT السابقة دون قبض آخر.

## المجدول

`finance_private.run_due_subscription_invoices(batch_limit)` خاص بقاعدة البيانات، يختار آخر فترة مدفوعة انتهت، مع mode automatic ودون تعليق/إلغاء. المفتاح مشتق من التاجر وanchor. إعادة التشغيل تعيد الفاتورة، ولا تنتج فترات/ديونًا متراكمة.

يستبعد مجدول legacy حسابات C8 من دفعاته مع الحفاظ على خوارزميته ومفاتيحه للحسابات الأخرى، حتى لا تستنفد الحسابات المنضمة حد الدفعة القديمة. تحديث تفضيل التجديد القديم أو جدولة خطة قديمة محظوران لحساب C8.

المحاولة التي تفشل بسبب خطة غير صالحة تتراجع في subtransaction، وتسجل failure metadata خاصة بلا أسرار؛ لا يبقى مفتاح رفض يمنع الفوترة بعد تصحيح الخطة. حساب معيب لا يوقف بقية الدفعة. لا تمنح الفاتورة فترة مدفوعة.

المهاجر **لا ينفذ cron.schedule** ولا يضيف امتدادًا. بعد الاختبارات ومراجعة المالك فقط يمكنه تجهيز pg_cron في Supabase وتسجيل أمر قاعدة خاص: `select finance_private.run_due_subscription_invoices(50);` بمالك الدالة دون JWT. إنشاء الجدولة وتفعيل scheduler_enabled قرار المالك، وليس خطوة نفذتها هذه المهمة. على بيئة اختبار يجب إثبات تكرار وتشغيل المجدول الفعلي، لا الاكتفاء بتشغيل helper يدويًا.

## الأهلية والتوافق

الحساب المنضم يحتاج قبول المتجر/التاجر وأحد active أو grace_period، دون suspended/cancelled. الحالات مشتقة من الخادم والتواريخ، لا من علم حالة قديم أو تشغيل المجدول. تغيير حالة إدارية لا يعدل دينًا أو يرد نقدًا.

الحماية النهائية BEFORE INSERT على store_orders؛ لا trigger على UPDATE لفرض اشتراك على طلب قديم. يؤخذ قفل share للتاجر لمنع تعارض التعليق/القبض مع admission. للـC8 فقط يُثبت created_at بوقت إدخال خادمي فعلي: now() في معاملة بدأت قبل القبض قد يسبق بداية الفترة المدفوعة. يتسق snapshot العمولة مع168 ساعة لـC8 فقط، ويبقى مسار legacy ذي7 أيام دون تعديل. لا تتغير نسبة العمولة أو معادلتها أو قيود C4–C7.

quote يرفض سلة فيها متجر C8 غير مؤهل، ولا يحذف المتجر أو يخفض السعر بصمت. التأكيد النهائي يعيد التحقق؛ C3 يحفظ رفض C8_STORE_UNAVAILABLE ويرد رسالة عامة للعميل. يبقى فحص المستخدم والسلة والسعر والاستعادة قبل هذه المرحلة كما هو، بما فيه إعادة الطلب الموجود دون حظر استعادته بعد انتهاء اشتراك أحد متاجره. أي رفض يعيد subtransaction كاملة، فلا يبقى SUB جزئي.

لا إلغاء للطلبات السابقة، ولا منع للتحضير/التسليم أو C5/C6/C7 أو الاطلاع على الفواتير. لا حذف منتجات. الاستثناء الإداري: suspend/resume/cancel بتفويض مستقل وسبب، والإلغاء لا يلغي الفواتير ولا يسترد مدفوعاتها. الحساب cancelled لا يعاد تنشيطه بمجرد resume؛ إعادة إدخاله تحتاج قرار انتقال مستقل.
