# تصميم الأساس المالي

- كل صف في `merchant_subscriptions` يمثل فترة؛ القيد الجديد يمنع التداخل ويحافظ على السجلات القديمة دون Backfill أو دين تاريخي.
- فاتورة أساس واحدة فقط لكل فترة (`initial` أو `renewal`)؛ فواتير التصحيح متعددة ومحمية بـidempotency.
- الدفعات والتخصيصات منفصلة، والتخصيص append-only ويمنع اختلاف التاجر/العملة أو تجاوز قيمة الفاتورة أو الدفعة.
- `merchant_ledger_entries` هو المصدر الوحيد للتعرض: `increase_exposure - decrease_exposure`. لا تجمع أرصدة الفواتير أو التخصيصات معه.
- العمولة تحفظ نسبة مثبتة وقاعدة `store_order_totals.items_subtotal` عند إنشاء طلب المتجر، ثم تصبح مستحقة فقط عندما يصل التسليم إلى `delivered`. الربط مؤجل لمرحلة مستقلة.
- الائتمان مستقل عن المحفظة، لكل تاجر وعملة، ولا توجد مقاصة تلقائية مع أرباح التاجر.
