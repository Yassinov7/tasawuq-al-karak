# الأمان وRPCs المقترحة

- التاجر يقرأ فواتيره ودفعاته واشتراكاته وقيود دفتره فقط؛ لا ينشئ أو يعتمد دفعًا ولا يعدل الأسعار أو الحالات.
- الإدارة وحدها تنفذ RPCs إنشاء الفاتورة، تسجيل الدفعة، الاعتماد/الرفض، التسوية، والتصحيح.
- كل RPC مالية `SECURITY DEFINER` مع `search_path` ثابت، تحقق `is_admin()`، Transaction، `FOR UPDATE`، ورسائل خطأ غير حساسة.
- المنع ليس في الواجهة: Unique constraints وidempotency keys وRLS وAudit logs إلزامية.
- لا حذف لسجل مالي مؤثر؛ التصحيح بقيد عكسي مرجعي.
- لا تقبل RPC أي نسبة عمولة أو مبلغ أو عملة من العميل دون إعادة اشتقاقها من البيانات المحفوظة.
