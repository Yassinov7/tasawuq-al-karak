# استراتيجية الترحيل الآمن

1. فحص Schema الإنتاج ونسخة احتياطية وتجربة كاملة على بيئة اختبار.
2. إضافة الجداول الجديدة دون تغيير أرصدة `wallets` أو `wallet_transactions` التاريخية.
3. وسم الفترات الحالية بأنها legacy؛ لا تنشأ ديون تاريخية تلقائيًا.
4. ترحيل اللقطات المتاحة فقط؛ الفواتير التاريخية غير الموجودة توضع في قائمة مراجعة إدارية لا في DML تلقائي.
5. تشغيل النظام الجديد للاشتراكات الجديدة أولًا، ثم مراجعة تقارير الاتساق قبل تفعيل القيود التشغيلية.
6. لا إعادة حساب صامتة للأرصدة أو العمولات أو الطلبات السابقة.

قرار مطلوب: تاريخ القطع، ومعالجة الاشتراكات القديمة التي لها سعر محفوظ لكن لا إيصال دفع.
